# DB dictionary (v1)

## Notes

| Column | Type | Stored as | Description | Constraints |
|---|---|---|---|---|
| `id` | integer (4 bytes) | plaintext | Unique ID for the note | Primary key, auto-increment |
| `title` | bytea | **encrypted**, nonce prepended | The note's name, shown to the user | Nullable. 100 char max, enforced in Go *before* encrypting |
| `body` | bytea | **encrypted**, nonce prepended | The note's content | Not null, no length limit |
| `created_at` | timestamptz | plaintext, UTC | When the note was made | Not null, default now |
| `modified_at` | timestamptz | plaintext, UTC | When the note was last edited | Not null, default now, set by the app on every edit |

## Meta

A tiny key/value table for app-level settings.

| Column | Type | Description | Constraints |
|---|---|---|---|
| `key` | text | Setting name (e.g. `kdf_salt`, `schema_version`) | Primary key |
| `value` | bytea | The value | Not null |

The salt isn't secret, so it's fine in plaintext. Storing a `schema_version` here makes future migrations much easier.

## Later additions (not v1)

**Users**

| Column | Type | Description | Constraints |
|---|---|---|---|
| `id` | integer | User ID | Primary key, auto-increment |
| `username` | text | Login name | Unique, not null |
| `auth_hash` | text | Password hash for login | Not null, separate from the encryption key |

**Note shares** (replaces the `ShareID` list)

| Column | Type | Description | Constraints |
|---|---|---|---|
| `note_id` | integer | The shared note | Foreign key to Notes |
| `user_id` | integer | Who it's shared with | Foreign key to Users |
| `wrapped_key` | bytea | The note's key, re-encrypted for that user | Not null |

Composite primary key on (`note_id`, `user_id`). Adding `user_id` to Notes (the owner) happens at this point too, and sharing implies a per-note key, which is the `wrapped_key` column.

**Version history** could become a `note_versions` table later (note ID, encrypted body, timestamp), so `modified_at` stays simple for now.

## Things that stay true
- Only `id` and the timestamps are readable by someone with DB access.
- Dates are UTC in the DB, and display format is decided in the CLI.
- Size limits on titles are checked in Go, since the DB only sees ciphertext.
